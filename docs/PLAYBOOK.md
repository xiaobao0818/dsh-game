## 2. 稳定下来的五层架构

```
┌─ core ────────── 纯函数：数学 / 可复现 RNG / 存档（无 DOM，Node 可跑）
├─ data ────────── 全部内容表：关卡 / 单位 / 敌人 / 升级 / 主题（数据驱动）
├─ sim ─────────── 玩法逻辑：固定步长 update，输入=命令，输出=状态+事件
├─ view ────────── 渲染/输入/音频：只读状态，不写玩法
└─ tooling ─────── serve / build-single / sim / headless / check
```

铁律：
1. `sim` 不 import DOM，不 `Math.random`，不读时间；同一 seed 必须逐帧一致。
2. `view` 不得修改玩法状态（修复 bug 时先问"这是逻辑还是表现"）。
3. 内容表是唯一数值来源；代码里不出现魔法数。
4. 单文件构建是交付物，不是调试附件；构建后必须断言零外部引用。

## 3. 七阶段开发流程（每个项目的实际路径）

1. **研究/拆解**：看原版视频/包体/公开资料，写 `RESEARCH.md`（玩法循环、数值、UI、音频清单）。
2. **设计圣经**：一句话定位 + 核心循环 + 30 秒体验 + 关卡结构 + 失败条件 + 情绪基调（`DESIGN_BIBLE.md`）。
3. **数值与契约**：预算曲线、产出/消耗比、Boss 阈值；把"数据契约 + 效果键白名单"写进 `CONTRACTS.md`。
4. **垂直切片**：先 1 个可玩关卡跑通"输入→反馈→结算→重开"，再扩内容。
5. **内容生产**：程序化美术/音频先行保证可玩；正式美术走 manifest + 双轨替换；关卡用生成器 + 门禁。
6. **测试与调优**：无头 sim（机器人）、求解器、渲染冒烟、CDP UI 冒烟、性能与体积预算、真机适配。
7. **交付与复盘**：单文件/工程版、README、上线检查清单、修复记录、变更日志；把新坑写成断言。

## 4. 关键技法库（按价值排序）

1. **纯逻辑 sim + 命令/事件/状态三段契约**（horde `sim.js`）：1473 行战斗逻辑跨 Canvas/Cocos 零改动；
   Node 里跑 30 关平衡与随机路径测试。→ 生成器把它作为硬约束。
2. **波次编译成扁平时间轴**（horde）：波次在开局编译为 `[{t,type,count…}]`，运行期只推进游标，
   从制度上防止瞬时爆兵。→ horde 基因采用同款。
3. **固定步长 + 复位式主循环**：1/60 累加器，单帧最多追 4 步；后台切回不雪崩。
4. **可复现 RNG**：mulberry32，种子 = 业务 id × 质数（关卡/机器人/生成器）。测试失败可 1:1 复现。
5. **生成→求解→重放三同一**（停车）：`replayFrames()` 与 `solve()` 同时通过才入库，且与浏览器
   `autoStep()` 共用同一函数 → "验证过=玩家能过"成为恒等式。→ 解谜基因采用求解器门禁。
6. **三阶段关卡生成**：构造（<1ms）→ 三门禁（可解/步数/难度区间）→ 候选池按目标胜率挑；
   章末难关自动换位。→ 排序/合成基因的关卡生成。
7. **配置表→瘦模型适配层**（细胞）：637 关/446 技能原始表经 datamodel 归一化，业务只依赖 MODEL。
8. **方向性融合建模**（细胞）：`fuse(host, material)` 由 inherit/faction/branch 三个正交旋钮决定，
   A 融 B ≠ B 融 A 可在数值/技能/名称三处断言。
9. **状态机 + 事件总线**：菜单/战斗/结算/暂停互斥；UI 只订阅事件，避免"双结算/重复发奖"。
10. **数据驱动 + 效果键白名单**：升级节点用元组 DSL + mode 正则推导，150 节点只写 200 行，
    避免"该乘写成加"；引用完整性由校验脚本强制。
11. **世界坐标 0..1 + 单一 layout 映射**：一套数值适配手机/平板/桌面与换引擎，无像素魔法数。
12. **绘制双轨制**：`if (tex) { drawImage; return; }` 程序化兜底 → 零美术可玩、丢 PNG 即升级。
13. **美术提示词五层 schema**：prompt → anchor → safe_area → grid → manifest(`prompt_source`)，
    QA 自动验尺寸/alpha/32px 安全边。→ 正式美术接入规范。
14. **音频清单 + 运行时压缩表**：music/sfx manifest 记录源文件/裁切/字节；54→27 复用压缩；
    循环 BGM 用 WAV 防接缝；人声走 `atob` 内联而非 fetch。
15. **单文件打包器**：正则子集 ESM→IIFE + 内联 CSS/资源 + 三道自检（语法/无残留 import/无外部引用）
    + 两次构建 sha256 相同。→ 生成器内置同款。
16. **无头仿真 + 机器人**：机器人用与玩家相同的动作 API；断言全通关、时长区间、摆烂不通关。
17. **渲染冒烟**：全关卡逐关进入、投几步、跑 2 帧、抓 `exceptionThrown`+`console.error`+`Log`。
18. **CDP 浏览器断言**：`window.__game` 暴露诊断（scene/fps/rule.debug/save），截图落盘人工验收。
19. **性能预算**：中端机 60fps；网格 swap-pop 清理、drawBuf 复用、按 y 排序、对象池；
    单文件体积预算 300KB~1.2MB。
20. **回归即断言**：把每个已修 bug 变成 check 里的一条断言（惊鸿 6/6），比覆盖率更有效。

## 5. 玩法设计公式

- **一个动词**：每 5 秒重复的动词决定品类；所有系统服务它。
- **核心循环**：操作 → 即时反馈（飘字/粒子/音效/屏震）→ 资源 → 更大操作 → 更难的挑战。
- **局内 90~180 秒**：3~6 波；首段教学、中段加压、末段 Boss；失败 1 秒内可重开。
- **难度锯齿**：Boss 关 ×1.1~1.65，之后回落 ×0.6~0.8；用仿真验证而不是拍脑袋。
- **经济**：产出/消耗 1.15~1.35；前期给选择、后期给升级；首通奖励 > 重复刷。
- **局外长线**：星级/解锁/图鉴/无尽/成就，给重玩理由。
- **爽感优先于拟真**：命中停顿、屏震、数字、慢镜、特写，成本低收益高。
- **3 秒看懂**：标题页一句话说明目标；第一关 30 秒内完成一次完整循环。

## 7. 踩坑库（症状 → 根因 → 修法）

1. 敌人打不死/进度卡住 → 某字段 `undefined` 参与数值，NaN 扩散 → sim 断言 `Number.isFinite`。
2. 测试通过但玩家过不了 → 求解器按不同 tick，亚拍差被放大 → 求解器与游戏共用同一重放。
3. 换引擎后修复丢失 → 移植补丁只改了一侧 → 补丁双向同步 + 同源校验。
4. 切 tab 内存涨 → 节点只摘不销毁 → 先摘再 destroy。
5. iOS 无声 → 初始化即 `new AudioContext` → 只绑手势，pointerdown 内 unlock。
6. 点击无反应 → 启动遮罩未移除 / HUD 命中区后算 / pointer-events 被父层吞掉。
7. 按钮点不中 → 指针未换算设计分辨率 → 统一 `layout.toDesign()`。
8. 结算重复发奖 → 回调无幂等 → settleId + 已领标记。
9. 存档被旧内存覆盖 → beforeunload 自动保存覆盖导入结果 → suppressAutoSave。
10. 单文件白屏 → `file://` 下 fetch/img 失效 → 构建期内联 data URI。
11. 包体暴涨 → 25MB 单文件 143 张 data 图在 ArkWeb 加载不完 → 工程版 + rawfile。
12. 鸿蒙路径报错 → hvigor 拒绝非 ASCII 工程路径 → 构建前置守卫。
13. 循环 BGM 有缝 → MP3 编码间隙 → 用 WAV / 精确循环点。
14. 难度陡增 → 综合战力缩放（坦克堆血不堆输出）→ 按输出维度缩放。
15. 首领战拖 2~3 分钟 → 血量按玩家战力而非目标时长 → 以"击杀时间 25~45s"反推。
16. 文档与代码漂移 → 公式只写在文档 → 公式单点断言。
17. 随机不可复现 → 测试/生成器用 Math.random → 固定种子 + 注入 RNG。
18. 关卡不可解 → 生成后没验证 → 求解器门禁 + 候选池。
19. 摆烂也能通关 → 只有"能赢"测试没有"会输"测试 → 加 idle 反例断言。
20. 帧率塌方 → 每帧 new 对象/重建路径 → 池化与缓存、按 y 排序绘制。
21. 广告按钮点不动 → 横屏 CTA 掉出视口 → 正文滚动 + 固定 actions + 双视口截图审计。
22. 崩溃后无法续玩 → 存档 schema 无版本 → 带版本 deepMerge 迁移，坏档回退默认。
23. 生成器产出千篇一律 → 只有模板没有内容策略 → 主题词库 + 难度曲线 + 种子化细节。
24. 自动化测试互相污染 → import 源码单例导致多实例存档 → 只经 `window.__save` 访问。
25. 单文件构建不稳定 → 依赖顺序/循环引用 → 拓扑序 + 循环检测 + 语法校验。

## 10. 从"手工项目"到"一句话生成"：抽象结论

把上述共性压缩成一台生成器需要四个决定：

1. **固定壳层**：标题/选关/战斗/暂停/结算/设置/说明/存档/音频 = 一套 `app.js`，所有游戏共用。
2. **可插拔玩法基因**：每个基因只写 `rules/<genre>.js`（update/draw/pointer/bot）+ `buildContent()`（内容与关卡生成）。
3. **题材与内容分离**：`theme`（调色板/音乐调式/词库）与基因正交，10 题材 × 6 基因 = 60 种组合。
4. **交付闸内置**：数据/无头仿真/单文件/浏览器冒烟/截图，生成即验收；机器人策略让"能不能通关"可自动证明。

「游戏工坊」插件正是这四点的实现：`game_forge` 一句话 → 工程 + 单文件 + 自检；
`game_build` / `game_check` 支持后续手工迭代；`game-studio` skill 承载本方法论的作业手册。

## 11. 双运行时：HTML5 与 Cocos Creator 3.8

工作区里的《僵尸围山门》给了一个明确结论：**玩法逻辑与渲染分家后，换引擎只换表现层**（`sim.ts` 1473 行与
`sim.js` 逐行一致，8 个数据文件 diff 0~1 行）。插件据此做成双运行时：

```
同一份 content（关卡/数值/主题） + 同一份 rules（update/pointer/bot）
        ├── HTML5 目标：Canvas2D 立即模式渲染 + WebAudio + DOM 输入 → 单文件离线版
        └── Cocos 目标：GameRoot(宿主) + CanvasSurface(Canvas2D→Graphics/Label 桥) + Cocos 输入/循环
```

### 11.1 为什么用「绘制桥」而不是重写一套 Cocos 玩法

- 6 个基因共 ~3500 行规则/表现代码，重写两套必然漂移（工作区吃过「补丁只改一侧」的亏）。
- 规则层的绘制只用到 Canvas2D 的一个**小子集**：路径（arc/ellipse/quadratic/bezier/arcTo）、
  fill/stroke、fillRect、fillText/strokeText/measureText、线性/径向渐变、save/restore/translate/scale/rotate、
  globalAlpha、lineWidth/cap/join、clip、drawImage（仅离屏缓存）。
- `CanvasSurface` 把这套子集映射到 Cocos `Graphics`（一个节点按序重放路径，`fill/stroke` 通过 pathOffset 分段消费）
  + `Label` 池（文字）+ 变换矩阵（把设计坐标 左上原点/y 向下 映射到节点中心/y 向上）。
- 结果：**同一份规则代码**在 HTML 与 Cocos 里跑；Cocos 工程里 `assets/scripts/game/` 与 HTML 工程的 `js/` 同源。

### 11.2 Cocos 工程的生成与验收

- 工程骨架：`package.json`(creator 3.8.8) + `settings/v2`（设计分辨率按横竖屏 1280×720 / 720×1280）+ `assets/scenes/Main.scene`
  （Canvas + Camera + GameRoot 组件，脚本 uuid 用 Cocos 的压缩 uuid 规则写入场景）+ `tsconfig.json`。
- 构建：Cocos CLI `--project <dir> --build "platform=web-mobile;debug=true" --nologin`；
  工作区实测首次 ~40~50s（构建引擎缓存），之后 5~12s；CLI 偶发非 0 退出但产物已生成，按产物判定并重试。
- 冒烟：无头 Chrome 必须带 WebGL 软件渲染参数（`--enable-unsafe-swiftshader --use-angle=swiftshader --ignore-gpu-blocklist --enable-webgl`），
  通过 CDP 打开 `build/web-mobile/index.html`，断言 `window.__game` 就绪 → 进关 → 机器人快进 → 结算 → 三张截图。
- 性能：无头软件渲染 ~20~26fps；**有头/真机 60fps**（同一构建用有头 Chrome 实测 59.98）。不要把无头软件渲染数字当性能结论。

### 11.3 Cocos 桥的已知近似（写进生成工程 README）

| 能力 | 处理 |
|---|---|
| 线性渐变 | fillRect 按 14 条带模拟；路径填充按包围盒取色（按钮/面板会略平） |
| 径向渐变 | 光晕/暗角直接省略（避免色带）；粒子/光球取中心色 |
| 阴影 / lineDash | 忽略（虚线变实线） |
| drawImage（离屏缓存） | 不可用；规则的背景缓存需检测 `ctx.drawImage` 回退为直接绘制 |
| clip | 只支持轴对齐矩形/路径包围盒（排序的卡片溢出裁切够用） |
| 文字 | Label 池；描边用 LabelOutline；始终位于 Graphics 之上 |

### 11.4 踩坑（本轮实测）

1. `LineCap/LineJoin` 不是 `cc` 顶层导出，要用 `Graphics.LineCap / Graphics.LineJoin`。
2. 渐变对象必须自己带 `addColorStop`（Cocos 无 CanvasGradient）。
3. 离屏 canvas + `drawImage` 在 Cocos 无对应物：`ensureBg()` 必须检测 `typeof ctx.drawImage !== 'function'` 回退。
4. 场景里脚本组件 `__type__` 是 **uuid 压缩串**；自定义 uuid 需按 Cocos 算法压缩，否则场景加载不出组件。
5. 无头冒烟若无 WebGL 标志 → 黑屏/报错；Cocos 构建产物必须用 HTTP 服务（`file://` 会被 CORS/相对路径坑）。
6. 设计分辨率要在 `settings/v2/packages/project.json` 与场景 Canvas 的 UITransform 同时改，只改一处会错位。
